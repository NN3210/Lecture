# 結果統合の指示（Sonnet サブエージェント用）

目的：`codex/results/資料NNN.md`（Codex が書いた 1 資料 1 ファイルの構成抽出）を、バッチ単位で 1 ファイル `codex/merged/<batch_id>.md` に圧縮する。
最終的に `02_各資料の構成抽出.md` へ連結し、Fable が全資料を横断して「順序の抽象化」を行う材料にする。
**内容を創作しない。** 結果ファイルに書いてあることだけを短くする。無いものは「—」。

## 段階コード（話題の粗い分類。順番の比較に使う）

| コード | 内容 |
| --- | --- |
| WHY | なぜ座標・基準が要るか（導入の問い、身近な例、失敗例） |
| COORD | 座標とは何か（原点・軸・単位、座標の読み方、座標系の種類の俯瞰） |
| SHAPE | 地球の形（球・楕円体・GRS80/WGS84 の寸法、扁平率） |
| GEOID | ジオイド・平均海面・重力方向・水準面 |
| HEIGHT | 高さの種類（標高・楕円体高・ジオイド高、h = H + N） |
| LATLON | 緯度経度の定義（測地緯度・地心緯度、度分秒、子午線・赤道） |
| ECEF | 地心直交座標（XYZ）、基線ベクトル |
| DATUM | 測地系・基準系（NAD27/83、WGS84、ITRF、JGD2000/2011、旧日本測地系、基準点・原点） |
| TRANSFORM | 測地系変換・座標変換（平行移動・回転・7 パラメータ、変換ソフト） |
| PROJ | 投影の概念（曲面→平面、ひずみ、正角・正積・正距、展開可能面） |
| MAPPROJ | 投影法の種類（円筒・円錐・方位、メルカトル・ランベルト等） |
| TMUTM | 横メルカトル・ガウス・クリューゲル・UTM（ゾーン・中央子午線・0.9996） |
| PLANE | 州平面座標 SPC・平面直角座標系（19 系）・ゾーン選択・原点加数 |
| SCALE | 縮尺係数・標高補正・グリッド距離と地上距離の換算 |
| AXIS | 軸の向き（X 北 Y 東）、象限、北の種類（真北・磁北・座標北）、方位角・方向角 |
| CALC | 座標計算（順計算・逆計算、ΔX ΔY、トラバース、面積） |
| GNSS | GNSS 測位と座標の関係、受信機・機器の設定 |
| LAW | 法令・制度・測地成果の元期・セミダイナミック補正 |
| EX | 演習・例題・クイズ・まとめ・次回予告 |
| OTHER | 上記に入らないもの（括弧で 5 字以内の補足を付ける） |

## 出力形式（`codex/merged/<batch_id>.md`）

```
# 統合：<batch_id>（結果 N 件、OK n 件、NG m 件）

## 一覧

| No | 題（30 字以内） | 種別・言語・長さ | 機関 | レベル | 実在 | 段階数 | 導入型 | 段階コード列 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 004 | State Plane Coordinate System | 解説ページ・英・1 頁 | Penn State | 学部初年 | OK | 7 | 例 | WHY→PLANE→PLANE→DATUM→WHY→EX |

導入型は 問い / 例 / 歴史 / 定義 / 目次 / 不明 のどれか。
段階コード列は「扱う話題の順番」の各段階を順にコードへ置き換えたもの（同じコードが続いても省略しない。段階数と個数を合わせる）。

## 各資料

### 資料004：State Plane Coordinate System
- 順番：1 地形図の座標表示(WHY) → 2 原点からの距離(PLANE) → 3 東距北距の格子(PLANE) → 4 SPC の定義(PLANE) → 5 NAD27/83 の版(DATUM) → 6 大縮尺で使う理由(WHY) → 7 到達目標(EX)
- 導入：地形図の余白に並ぶ座標表示を読ませてから定義へ。
- つなぎ：座標表示→原点距離（図の数値を説明するため）／定義→版（単位と基準系で版を識別）／版→利用目的（明示なし）
- 工夫：実図の併記、同一図で緯度経度・UTM・SPC 比較、具体数値 1,970,000 ft、feet と NAD27 で旧版識別
- 無い段階：投影法・縮尺係数・変換例は無し。楕円体・測地系・UTM は既習扱い。
```

- 「順番」は 1 段階 12 字以内＋コード。段階は省略しない（結果ファイルの番号と同じ数）。
- 「つなぎ」は結果ファイルの中で理由が書かれているものを優先して 2〜4 本。理由が「明示なし」のものは「（明示なし）」と書く。
- NG（実在確認 NG）の資料は一覧の行だけ書き、「各資料」には `### 資料NNN：NG（理由 1 行）` だけ書く。
- 再生リストや講義一覧ページのように段階が講義題名だけのものは、そのまま題名を段階として書き、備考に「題名のみ」と書く。
- 個人名は書かない（結果ファイルに紛れていても機関名に置き換える）。
- 書く場所は `notes/session03_kai2_20261021/codex/merged/<batch_id>.md` だけ。git 操作はしない。他のファイルに書かない。
- 最後の返答は「N 件統合、OK n、NG m、書いたファイルのパス」の 2 行だけでよい。

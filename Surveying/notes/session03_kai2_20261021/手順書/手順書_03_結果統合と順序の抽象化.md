# 手順書 03：Codex の抽出結果を統合し、「なぜ分かりやすいか・どの順番か・なぜその順番か」を抽象化する

作成日：2026-10-22。統括：Claude Code（Fable 5.1）。単純作業：Sonnet サブエージェント（トークン効率のため）。
入力：`codex/results/資料NNN.md`（手順書 02 の出力、1 資料 1 ファイル）。
出力：[02_各資料の構成抽出.md](../02_各資料の構成抽出.md)（全資料の圧縮版）、[03_順序の抽象化と理由.md](../03_順序の抽象化と理由.md)（横断の抽象化）。

## 1. バッチ単位の圧縮（Sonnet）

1. 指示書 [`codex/merge_instructions.md`](../codex/merge_instructions.md) を用意した。要点：
   - 段階コード（WHY / COORD / SHAPE / GEOID / HEIGHT / LATLON / ECEF / DATUM / TRANSFORM / PROJ / MAPPROJ / TMUTM / PLANE / SCALE / AXIS / CALC / GNSS / LAW / EX / OTHER）で各資料の「扱う話題の順番」をコード列に置き換える。これで資料どうしの順番を機械的に比べられる。
   - 1 資料あたり「順番・導入・つなぎ・工夫・無い段階」を 5 行に圧縮。創作禁止、無いものは「—」。
2. バッチ（p01〜p06、v01〜v06、再実行 v01r・r02）が終わるたびに Sonnet サブエージェント（model: sonnet）を 1 本起動し、`codex/merged/<batch_id>.md` を書かせる。
   - プロンプトは「指示書を読む → 対象 10 ファイルを全部読む → 出力 1 ファイル → 返答は 2 行」のみ。統括側の文脈に結果本文を戻さない。
3. 全バッチ分がそろったら `python -I scripts/kai2_concat_merged.py` で `02_各資料の構成抽出.md` に連結する（一覧表を先頭に集約、各資料の節を No. 順に並べる）。

## 2. 横断の抽象化（Fable）

`02_各資料の構成抽出.md` の一覧表（段階コード列）と各資料の「つなぎ」「工夫」を読み、次の問いに答える形で `03_順序の抽象化と理由.md` を書く。

1. **どの順番か**：段階コードの出現順を集計する（各コードが資料の前半・中盤・後半のどこに出るか、どのコードの直後にどのコードが来やすいか）。よくある骨格を 2〜4 型に分ける（例：概念先行型、投影先行型、計算先行型）。
2. **なぜその順番か**：資料が「明示している」つなぎの理由を集め、同じ理由をまとめる（「高さの基準が決まらないと水平位置の基準が決まらない」「ひずみを知らないと UTM の 0.9996 が理解できない」など）。資料が明示していない理由は、統括側の推測として区別して書く。
3. **なぜ分かりやすいか**：「工夫」を種類別（実物の図・比喩・数値例・反例・クイズ・段階ごとの小まとめ）に集計し、どの段階でどの工夫が使われているかを対応付ける。
4. **欠けると詰まる段階（飛び石）**：多くの資料が必ず踏んでいる段階（出現率が高いコード）と、前提として要求される順序対（A が B より前に来る率）を列挙する。これが改 2 の「抜けチェック表」になる。

## 3. 改 1 との照合

[改1_構成診断.md](../改1_構成診断.md) の「順番の問題」「候補の欠け」を、上の抜けチェック表と順序対で裏付けまたは棄却し、`04_改2構成案.md` の「順」「k1:NN / new:ID」「備考」に反映する（手順書 04）。

# lecture-storyline-guide — 講義スライドを一本の筋でつなぐ講師用解説 HTML

## 目的

項目ごとに作られたスライドは、網羅性は高くても「全体を通して何をしているのか」が見えにくく、教える側が語りにくい。
このスキルは、既存のスライドを変えずに、**講師が読む解説 HTML** を 1 本作る。読めば次が分かる状態にする。

1. この回がどういう思想で並んでいるか（一文で言える「筋」と、何度も繰り返す 2〜3 語）
2. どんな背景（数学・物理・歴史・制度・専攻との接続）があるか
3. 学生に何を意識させ、節と節の間で何を言えば一本の線として届くか

第3回「測量の座標」で作った実例が `Surveying/materials/slides/第03回_測量の座標/講師用解説_思想と教え方.html` にある。新しい回を作るときは、まずこの実例を開いて体裁と密度を確認する。

## 入力（読む順）

| ファイル | 読む目的 |
| --- | --- |
| `materials/slides/第NN回_テーマ/slides.md` | 全枚。見出し・本文・発表者ノート（`<!-- -->`）を全部読む。ノートに「なぜここにあるか」の手がかりが多い |
| 同フォルダ `lesson_plan.md` | 到達目標、時間配分、節ごとの枚の表、飛ばせる枠、過去問照合 |
| 同フォルダ `README.md` | 枚数と節の番号の対応表（スライド番号を正確に引用するために使う） |
| `materials/lecture_plan_13.md` | 全 13 回の中での位置、前後の回との接続、設計方針 |
| `materials/slides/_guidelines/slide_guidelines.md` | 全回共通の作り方（記号の固定、1 枚 1 分、節末の確認） |
| 前の回の講師用解説（あれば） | 繰り返す言葉・対比の連続性を保つ |

slides.md が長い（1000 行超）ときは 2 回に分けて全部読む。途中までで書き始めない。

## 手順

### 1. 筋を見つける（書く前に、頭の中で）

次の問いに順に答え、答えが一文で言えるまで考える。これがこの文書の価値の 9 割。

1. **この回の内容を一文で言うと何か。** 「○○を学ぶ」ではなく「○○は△△で決まる。だから□□になる」の形（主張＋理由＋帰結）。
   例（第3回）：「機器が測れるのは形（距離と角）だけで、位置は約束で決まる。地球は曲がり・でこぼこで・動くから、約束は階層になる。」
2. **何度も口にする言葉を 2〜3 語に絞る。** 例：「約束」「形と置き場所」「幾何と物理」。個々の数値や制度がすべてこの語に帰着するか確かめる。
3. **全体を貫く対比を 2〜4 個取り出す。** 各節の内容と試験の誤文が、どの対比に帰着するかを表にできること。
4. **「地図」を作る。** 階層・梯子・流れ図・時間軸のどれかで、授業中ずっと板書に残せる 1 枚。各節がその地図のどこに当たるかを言えること。
5. **節の順序の理由を言う。** 「なぜこの節がこの位置にあるか」を一文ずつ。言えない節があれば、それが構成の弱点（第 8 節に正直に書く）。

### 2. HTML を書く

`references/template.html` をコピーし、`{{ }}` を埋める。章立ては固定（他の回と同じ形にして講師が読み慣れるようにする）。

| 章 | 内容 | 分量の目安 |
| --- | --- | --- |
| 0 要旨 | 一文の筋（強調ボックス）、繰り返す言葉 2〜3 語 | 300 字 |
| 1 思想 | 「この分野にとって○○とは何か」。手順 1 の答えを 3〜4 小節で。対比の表、地球や対象の性質 → 生じる問題 → 対応する節の表 | 1500 字 |
| 2 一本の筋 | 地図（CSS の梯子または図）、節ごとの役割と「残す一文」の表、**節と節の橋渡し（最初の 30 秒で言う言葉）** | 2000 字 |
| 3 背景 | 数学・物理・歴史（年表）・制度・専攻への接続。スライドに書いていないが講師が持っていると話が太くなるもの | 2000 字 |
| 4 節ごとの教え方 | 各節に、位置づけ・肝となる枚・「こう言う」・「つまずき」・飛ばせる枚 | 節あたり 500 字 |
| 5 試験の型を思想で読む | 定番の誤文 → 取り違えている対比 → 正しい読み | 表 10〜15 行 |
| 6 学生の質問への備え | 想定質問 6〜8 件と答え | 各 100 字 |
| 7 時間が押したとき | 筋を切らない削り方の順位と、削らない「背骨」の枚 | 表 |
| 8 構成の弱点と改訂案 | 筋が見えにくい原因を正直に。改訂するなら効果の大きい順に 3 点 | 500 字 |

書き方の規則:

- **スライド番号を具体的に引く**（「22 枚目」）。README の対応表で番号を確定してから書く。
- **言い回しは講師がそのまま口にできる文**にする（「〜です」「〜か。〜だから」）。説明文ではなく台詞。
- 背景の年号・数値は、スライドか lesson_plan の「確認した事実」にあるものを優先し、それ以外は一般に確立した事実だけを書く。断定できない値は「程度」「所がある」と幅を持たせ、末尾の注記で確認を促す。
- 同じフォルダの図は相対パス（`diagrams/xxx.png`）で埋め込む。外部 URL の画像は使わない。
- 日本語。公開リポジトリなので個人名・連絡先・学生情報・企業名は書かない（協力企業A、担当者 等）。
- 文字コード UTF-8、CSS はインライン、JavaScript なし。1 ファイルで完結させる。

    def __init__(s): super().__init__(); s.st=[]

    def handle_endtag(s,t):
        if s.st and s.st[-1]==t: s.st.pop()
        else: print('mismatch',t,s.st[-3:])
p=P(); p.feed(open('講師用解説_思想と教え方.html',encoding='utf-8').read()); print('unclosed:',p.st)

さらに自分で読み返して確認する: スライド番号が README の表と一致するか、橋渡しが節の数だけあるか、「残す一文」が全節にあるか、第 8 節が空疎な賛辞になっていないか。

### 4. 保存・記録

- 保存先: スライドと同じフォルダ `materials/slides/第NN回_テーマ/講師用解説_思想と教え方.html`
- 同フォルダ `README.md` の「ファイル」節に 1 行追加（「講師が読む文書。学生には配布しない」を明記）
- `notes/worklog.md` に日付付きで 2〜5 行
- `git status` を確認し、**自分が作ったファイルだけ** add して commit、push。並行作業中の別エージェントの未追跡ファイルが混ざっていたら触らない。

## やらないこと

- スライド本体（slides.md / pptx / pdf）を変更しない。改訂案は第 8 節に書くだけにし、反映は別の依頼で行う。
- 要約を作らない。各枚の内容を並べ直したものは「項目の羅列」の再生産になる。書くのは筋・背景・語り方。
- 褒めない。弱点は構成の側から具体的に書く（「節末の試験の型で物語が切れる」「3-3 が A・B・A で混ざる」のように）。

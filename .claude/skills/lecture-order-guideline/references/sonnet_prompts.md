# Sonnet サブエージェント用プロンプト（段階 3）

どちらも `Agent` ツールで `model: sonnet` を指定して起動する。`{{ROOT}}` は作業ディレクトリ（例 `notes/session05_traverse_20261101`）、cwd は科目のプロジェクト直下（`Surveying/`）。
返答を 2 行に限るのは、統括の文脈に 100 件分の本文を戻さないため。結果はファイルで受け取る。

## 1. バッチ圧縮（バッチごとに 1 体。独立なので 3〜4 体を同じメッセージで起動してよい）

```
あなたは講義設計の下請けです。日本語で作業します。

1. まず指示書 {{ROOT}}/codex/merge_instructions.md を全部読む。
2. 対象バッチ {{BATCH_ID}} の結果ファイルを全部読む：
   {{ROOT}}/codex/results/資料{{NO1}}.md、資料{{NO2}}.md、…（{{N}} 件。番号：{{NUMBERS}}）
3. 指示書の出力形式どおりに {{ROOT}}/codex/merged/{{BATCH_ID}}.md を 1 ファイル書く。
   - 一覧表の行数 = {{N}}。1 件も落とさない。書き終えたら行数を数え直す。
   - 段階コード列は指示書の表のコードだけを使う。段階数と個数を合わせる。
   - 内容を創作しない。結果ファイルに無いものは「—」。個人名は書かない。
4. 書く場所は上の 1 ファイルだけ。git 操作はしない。他のファイルに書かない。

最後の返答は「N 件統合、OK n、NG m」と「書いたファイルのパス」の 2 行だけ。本文を貼らない。
```

`{{NUMBERS}}` は `codex/batches/batch_<id>.md` の No. 列（`make_merge_instructions.py --list-batches` が出す）。

## 2. つなぎの理由・工夫・無い段階の整理（1 体）

```
あなたは講義設計の下請けです。日本語で作業します。

{{ROOT}}/02_各資料の構成抽出.md の「## 各資料」以下、実在 OK の資料すべてについて「順番」「導入」「つなぎ」「工夫」「無い段階」の行を読み、
{{ROOT}}/codex/つなぎ理由と工夫の整理.md を次の 5 節で書く。

# つなぎの理由・工夫・無い段階の整理（資料横断）
（元ファイル名、OK 件数、生成日、「件数は概数。資料に書かれた範囲のみ。書かれていない理由は補っていない」の注意書き）

## 1. 段階ペアごとの「なぜ次に進むか」（資料が明示した理由）
- 段階コードのペア（例「WHY → COORD / DATUM」）を小見出しにし、その下に「資料NNN・NNN：理由の要約（1 行）」を並べる。
- 同じ理由は 1 行にまとめ、資料番号を列挙する。「明示なし」のペアは最後に「分野内の並び（明示なし が多い型）」としてまとめる。
- 理由を補わない。資料の「つなぎ」の行に書いてあるものだけ。

## 2. 工夫の種類別の対応表
| 工夫の種類 | 使われている段階 | 資料番号 | 具体例（短く） |
種類は：実物の図・写真／比喩／数値例（1 問を最後まで）／反例・失敗例／クイズ・問い／段階ごとの小まとめ／対比表／実演・道具／歴史／その他。

## 3. 「この資料に無い段階」の集計
| 無いと指摘された段階（コード） | 件数 | 代表的な指摘（資料番号） |

## 4. 導入のしかたの型
| 導入型 | 件数 | 典型例（資料番号と 1 行） |

## 5. 気づき（5〜10 行）
資料横断で目についたこと（例「動画は末尾で問いを回収する」「試験対策は計算から入る」）。推測ではなく、複数の資料に共通して書かれていることだけ。

書く場所は上の 1 ファイルだけ。git 操作はしない。個人名は書かない。
最後の返答は「書いたファイルのパス」と「§1 のペア数・§2 の行数」の 2 行だけ。
```

## 3. 起動のしかた（統括側）

- `Agent` ツール、`subagent_type: general-purpose`、`model: sonnet`、プロンプトは上をそのまま（placeholder を埋める）。
- 圧縮は 1 バッチ 3〜5 分。通知が来たら `concat_merged.py` で件数を検算し、落ちたバッチだけやり直す。
- Sonnet の返答が 2 行を超えて本文を貼ってきても、読まずに捨てる（ファイルが正）。
